# V7 audit — 2026-08-23

## Scope

This audit records the state of the uploaded repository before the V9 redesign. It exists so historical benchmark behavior is not confused with the new architecture.

The source result file was:

`results/20260823T183430928405Z-eval-v1-prompt-comparison/trials.jsonl`

At the time of the audit it contained 289 completed V7 trials, including all five repeats of all 40 single-document cases (200 single-document trials).

## Actual V7 single-document result

Across the 200 complete single-document trials:

- top-1 / first-read required-document hit: **157 / 200 = 78.5%**;
- required document eventually read: **188 / 200 = 94.0%**;
- end-to-end success: **188 / 200 = 94.0%**;
- answer success conditional on the required document being read: **188 / 188 = 100%**;
- attribution success on those successful cases: **188 / 188 = 100%**;
- only **51 / 188 = 27.1%** of eventual-discovery cases had zero reads after complete discovery.

The important conclusion is that the 94% end-to-end score was not primarily an answer-extraction problem. The dominant problem was metadata discovery, followed by unnecessary continued reading.

Typical confusions were semantically understandable:

- D-8 duplicate-billing exception -> standard refund policy;
- PINE-6 partner exception -> base partner approval policy;
- region-qualified standard refund -> global standard refund policy;
- P-17 severity override -> base severity classification;
- Opal object ceiling -> Nova/Atlas product-limit documents instead of storage-class capacity;
- Crown concurrent capacity -> compute-tier definition instead of compute quota.

These are exactly the boundaries activation metadata should make explicit.

## Why V7 over-explored

V7 mixed two decisions after every read:

- `read_document` remained available;
- `submit_answer` was also available.

The model repeatedly had to decide whether to keep searching or stop, even after the evidence was already sufficient. The full metadata catalog and every opened body were rebuilt into every stateless call. This created both extra context and a repeated opportunity to choose another read.

## V9 design response

V9 separates the concerns:

1. metadata-only structured selection with an explicit primary document and optional additional documents;
2. disclosure of only those selected bodies;
3. a forced evidence-resolution decision;
4. at most one additional metadata-selection round when the evidence resolver can name a concrete missing evidence need.

Descriptions were rewritten as activation metadata: WHAT + WHEN + a discriminating boundary where useful. User-visible routing markers such as D-8, PINE-6, P-17, MIG-2 and EX-TEMP are allowed in metadata; hidden answer values remain in document bodies.

Because these changes were informed by EVAL-v1 failures, `eval-v1` must now be treated as a **validation** set. A new frozen held-out dataset is required before making a final generalization claim.
